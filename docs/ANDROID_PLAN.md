# OrderFlow Terminal для Android: план

План на 9 октября 2026 года. Основа — разбор ПК-версии [Hxck3r/orderflow](https://github.com/Hxck3r/orderflow) (версия 0.3.0, коммит `7502311`). Целевое устройство — Galaxy S25 Ultra. Главное — полноценный футпринт и ордерфлоу-индикаторы.

## Коротко

- **Ядро ПК-версии переносится на телефон почти без изменений.** Это `of-core`, `of-feed`, `of-storage`, `of-engine`, около 32 тыс. строк. От операционной системы в них зависят только два места: TLS и папки данных. Биржи, сведение 11 потоков, бары, футпринт, дельта, VWAP, CVD, профиль, Big Trades, поглощение, давление и запись на диск на телефоне считаются тем же кодом.
- **Футпринт рисуется тем же кодом, что на ПК.** На ПК график написан на egui и wgpu (`chart/`, `render/`, около 12 тыс. строк). Оба работают на Android: в eframe 0.36.2 есть фича `android-game-activity`, а wgpu рисует через Vulkan на Adreno 830. Поэтому футпринт, его настройки и все индикаторы на телефоне будут выглядеть как на ПК, и переписывать их не придётся.
- **Что пишется заново:**
  1. мобильная оболочка: экраны вместо вкладок-доков, жесты вместо мыши, нижние панели вместо меню;
  2. тонкий слой на Kotlin (около 300 строк): запуск, фоновая служба, уведомления, жест «назад»;
  3. сборка APK в GitHub Actions.
- **Порядок работ:** спайк (живой футпринт на S25 Ultra) → MVP (футпринт, Volume Profile, VWAP, CVD, Big Trades, ликвидации) → остальные ордерфлоу-индикаторы → фон и оповещения → стакан и тепловая карта → рисование, демо и реплей.

## 1. Что в ПК-версии

| Крейт | Строк (без примеров) | Что делает | На Android |
|---|---|---|---|
| `of-core` | 1 300 | фиксированная точка, инструменты, сделки, календарь | как есть |
| `of-feed` | 6 200 | сокеты 6 бирж, REST, часы, история | как есть, кроме TLS (§3.3) |
| `of-storage` | 3 800 | форматы OFT1/OFC1/OBK1, запись, покрытие | как есть, кроме путей (§3.4) |
| `of-engine` | 20 500 | тики, серии, футпринт, все расчёты индикаторов, стакан, реплей | как есть |
| `of-app` | 28 400 | интерфейс egui + рендерер wgpu + настройки | ~25 тыс. строк — общая библиотека, ~2 тыс. — только ПК |

Почему перенос дешёвый:

- **Движок не знает про интерфейс.** Связь идёт только через `Engine::start(EngineConfig)`, `Command` (`SetSeries`, `SetRepaint`, …) и `Shared` с сериями под `RwLock`. Ни один из четырёх крейтов ядра не зависит от egui и не запускает процессов. Платформенный код в них — только `app_config_dir`/`app_local_dir`.
- **Рендерер написан для слабого железа:** один 48-байтный «uber-quad» на всё, сцена не пересобирается при прокрутке, кадр рисуется только на новые данные. На телефоне это экономит батарею. Snapdragon 8 Elite и Adreno 830 намного быстрее i3-1115G4 и Intel UHD, под которые терминал настроен.
- **Форматы файлов не зависят от системы.** Историю сделок с ПК (`data\ticks\…`) можно скопировать на телефон как есть, и футпринт за 30 дней появится сразу, без скачивания.
- **На Android сразу подходят шрифты Linux-сборки** (`theme.rs`, ветка `cfg(not(windows))`, Noto Sans из `assets/fonts`).

Что в `of-app` привязано к ПК и мыши (это и придётся менять):

- `app.rs`: раскладка `egui_dock`, верхняя строка и строка состояния, горячие клавиши. В нём же лежит запуск движка (`engine_config`, `start_engine`, `sync_book`, `restart_engine`, `sync_alerts`), а он нужен обеим версиям.
- `chart/mod.rs` читает мышь напрямую: `pointer.hover_pos()` для подсказок, `MouseWheel` с Ctrl/Shift для масштаба, `secondary_clicked` для меню, Shift+перетаскивание для измерения. При этом модель координат `chart/view.rs` (`pan`, `zoom_x`, `zoom_y`) от устройства ввода уже не зависит.
- `window_frame.rs`, `instance.rs`, `sound.rs`, `desktop.rs`, `main.rs` — только ПК.

## 2. Архитектура

Сравнил три подхода:

| Подход | Футпринт и индикаторы | Настройки (6.4 тыс. строк) | Кто поддерживает |
|---|---|---|---|
| **A. Rust + egui + wgpu, тонкий Kotlin** (выбран) | тот же код, что на ПК | тот же код, крупнее под палец | один язык, общий код с ПК |
| B. Нативный интерфейс на Kotlin/Compose + ядро Rust через JNI | график всё равно на wgpu из Rust: подсказки и надписи сейчас рисует egui, их пришлось бы переписать | переписать на Kotlin | два языка, две копии логики настроек |
| C. Телефон как клиент ПК-терминала | рисуется на телефоне, данные с ПК | — | ПК должен быть включён, нужен проброс сети; README ПК-версии прямо обещает, что ПК держать включённым не нужно |

Выбран A. Минусы egui на Android — непривычный вид, слабая экранная клавиатура, системные отступы — проверяются на этапе 0 и закрываются точечно (§7).

```
┌──────────────────────────── APK ────────────────────────────┐
│ Kotlin, ~300 строк                                           │
│   MainActivity : GameActivity  — полноэкранный режим, вырез,  │
│                                   жест «назад» → в Rust       │
│   FeedService (foreground)     — держит процесс в фоне       │
│   Notifier                     — оповещения, вибрация        │
├──────────────────────────────────────────────────────────────┤
│ libofmobile.so (Rust)                                        │
│   of-mobile   новое: android_main, экраны, жесты, профиль    │
│   of-ui       из of-app ПК: chart, render, settings, book,   │
│               dom, demo, drawings, alerts, запуск движка      │
│   of-engine · of-feed · of-storage · of-core   без изменений │
└──────────────────────────────────────────────────────────────┘
```

Структура этого репозитория:

```
orderflow_mobile/
  Cargo.toml              workspace; крейты ПК — git-зависимости с rev = "<коммит orderflow>"
  crates/of-mobile/       cdylib: android_main, оболочка, жесты, мобильный профиль настроек
  android/                Gradle-проект: app/, манифест, Kotlin-классы, иконка
  docs/ANDROID_PLAN.md    этот план
  .github/workflows/      проверки и сборка APK
```

Код ПК подключается по точному коммиту (`rev`). Мобильная версия обновляется на новую ПК-версию отдельным осознанным шагом: сдвинуть `rev` и пересобрать. Для разработки обеих версий сразу — `[patch."https://github.com/Hxck3r/orderflow"]` на локальную копию.

## 3. Изменения в ПК-репозитории

Без них нельзя использовать код графика из второго репозитория: сейчас `of-app` — только бинарник. Каждая правка ниже не меняет поведение ПК-версии. Проверка: `cargo test --workspace`, `clippy -D warnings` и CI на Windows и Ubuntu, как сейчас. Плюс запуск ПК-терминала тобой.

1. **Разделить `of-app` на библиотеку `of-ui` и бинарник `of-app`.**
   - В `of-ui` уходят `chart/`, `render/`, `settings/`, `book/`, `dom/`, `demo/`, `drawings.rs`, `traded.rs`, `format.rs`, `theme.rs`, логика `alerts.rs`, а из `app.rs` — запуск и пересборка движка (`engine_config`, `start_engine`, `set_repaint`, `sync_book`, `sync_options`, `restart_engine`, `sync_alerts`, `update_rates`) и `FrameStats`/`consume`, на которые ссылается `chart/mod.rs`.
   - В `of-app` остаются `main.rs`, раскладка доков, верхняя строка и строка состояния, `window_frame.rs`, `instance.rs`, `sound.rs`, `desktop.rs`, `logger.rs`.
   - Изменение механическое: файлы переезжают, логика не трогается.
2. **Слой ввода графика.** Сейчас `ChartView` сам читает мышь. Нужно разделить, *что* сделать с графиком, и *откуда* это пришло:
   - `probe: Option<Pos2>` — точка, по которой строятся подсказки и перекрестие. На ПК это наведение мыши, на телефоне — перекрестие после долгого нажатия или наведение S Pen. Сейчас позицию указателя напрямую читают 12 мест в `chart/` и ещё 4 в `book/` и `dom/`.
   - действия: прокрутка, масштаб по времени или цене с точкой привязки, сброс к последнему бару, меню в точке, измерение. Мышь ПК отображается в них один к одному, жесты телефона — своим отображением в `of-mobile`.
3. **TLS.** `of-feed/src/rest.rs` создаёт ureq с `TlsProvider::NativeTls`, `tokio-tungstenite` собран с `native-tls`. На Android `native-tls` — это OpenSSL: его пришлось бы собирать под NDK, и системные сертификаты Android он не видит. Для `target_os = "android"` нужен rustls с вшитыми корневыми сертификатами (`tokio-tungstenite` `rustls-tls-webpki-roots`, ureq `rustls` + `RootCerts::WebPki`). Это пойдёт в `[target.'cfg(target_os = "android")'.dependencies]`, так что дерево зависимостей Windows не меняется — правило из `CLAUDE.md` соблюдено.
4. **Папки данных.** `app_config_dir()`/`app_local_dir()` берут `APPDATA` или `XDG`/`HOME`. На Android `HOME` нет, папки выдаёт система (`Context.getFilesDir()`, `getExternalFilesDir()`). Нужна функция `of_storage::set_app_dirs(config, local)` (`OnceLock`), которую оболочка вызывает до всего остального.
5. **Профиль по умолчанию.** `AppSettings::normalize` и `Default` получают мобильные значения по умолчанию (§6) под `cfg(target_os = "android")` или параметром профиля.

GitHub-доступ этой сессии открыт только к `orderflow_mobile`. Чтобы делать правки 1–5 пулл-реквестами в `orderflow`, этот репозиторий нужно добавить в сессию. Вариант без второго репозитория — перенести мобильную версию в `orderflow` как ещё один крейт. Это проще для одного человека, но репозиторий ты уже завёл отдельный, поэтому план исходит из двух.

## 4. Экран и управление на S25 Ultra

### Экран

- 6.9″, QHD+ 3120×1440, по умолчанию Samsung включает FHD+ 2340×1080; 1–120 Гц (LTPO).
- egui считает в логических точках по плотности экрана, поэтому раскладка одинакова в FHD+ и QHD+. В QHD+ только чётче цифры в ячейках, но расход батареи выше.
- В горизонтальной ориентации экран около 830–890 × 380–410 точек, в зависимости от «Масштаба экрана» в настройках телефона. Точную цифру сниму на устройстве на этапе 0. Для сравнения, минимальное окно ПК-версии — 960×600: телефон в горизонтали почти той же ширины, но на треть ниже.
- **Горизонтальная ориентация — основная для футпринта:** 25–30 строк цены и 8–10 колонок по 90 точек (`bar_px` по умолчанию на ПК тоже 90).
- **Вертикальная — для стакана с лентой** и компактного графика.
- Полноэкранный режим со скрытыми системными панелями. Вырез камеры обходится по отступам, которые Kotlin-слой передаёт в Rust.
- **120 Гц только когда нужно.**
  - жесты рисуются с частотой экрана;
  - живые данные — с `live_fps` (на телефоне 15 вместо 20);
  - без данных и касаний кадров нет вовсе, и экран сам падает до 1–10 Гц.

  Этот режим уже реализован на ПК («без новых данных окно не перерисовывается»).

### Экраны

1. **График**, главный экран.
   - Вверху тонкая строка: чипы сохранённых графиков (например «1m FP», «5m», «1h»), индикатор связи, часы UTC.
   - Справа выезжающая колонка кнопок индикаторов: VP, VWAP, CVD, Big Trades, ликвидации, «Темп», стакан на графике. Долгое нажатие на кнопку открывает её настройки, на ПК это правый клик.
   - Внизу — панели CVD и статистики, как на ПК.
2. **Два графика рядом** в горизонтали: старший таймфрейм для контекста и футпринт для подтверждения. Это ровно твоя схема «контекст → VAL/VAH → поглощение и футпринт на уровне».
3. **Стакан** (вертикаль): лестница и лента из `dom/`, как вкладка «Стакан» на ПК.
4. **Тепловая карта.**
5. **Настройки** — те же страницы `settings::ui` с поиском и сбросом. Элементы крупнее, высота строки не меньше 40 точек. Числа вводятся своей цифровой клавиатурой, нарисованной в egui: экранная клавиатура Android через egui работает ненадёжно.
6. **Потоки**: строка состояния ПК в виде списка. По каждому потоку — состояние, задержка, доля объёма, активность, цена к медиане, сверка с архивом. Подсказки, которые на ПК открываются наведением, здесь открываются касанием.

### Жесты

| Жест | Действие | На ПК |
|---|---|---|
| Перетаскивание одним пальцем | прокрутка по времени (и по цене при ручном масштабе), с инерцией | перетаскивание мышью |
| Щипок, пальцы расходятся по горизонтали | масштаб времени | колесо |
| Щипок по вертикали | масштаб цены | Ctrl+колесо |
| Перетаскивание по оси цены / времени | масштаб по оси | то же |
| Двойное касание графика | к последнему бару и автоцена | End, двойной клик |
| Двойное касание оси цены | автомасштаб цены | A |
| Долгое нажатие | перекрестие; панель вверху показывает бар, ячейку Bid×Ask, дельту, уровень, Big Trade или ликвидацию под ним; ведите пальцем — перекрестие следует, касание — убрать | наведение мыши |
| Долгое нажатие → «⋯» на панели перекрестия | меню: VWAP от бара, копировать цену, оповещение на уровень | правый клик |
| Касание двумя пальцами | свечи ↔ футпринт | F |
| Наведение S Pen | подсказки как от мыши | наведение |
| Кнопка S Pen + провести | измерение диапазона: Δцена, бары, объём, дельта | Shift+перетаскивание |

- **Подсказки — в панели, не под пальцем.** На ПК подсказка всплывает у курсора, а на телефоне её закрыл бы палец. Поэтому подсказка выводится в закреплённую панель над графиком; работает она через тот же `probe` из §3.2.
- **Жест «назад» не должен закрывать приложение.** Android ловит его у левого и правого края экрана. «Назад» закрывает открытую панель или меню, а приложение — только с пустого графика. Kotlin-слой перехватывает событие и передаёт в Rust. Края графика исключаются из системных жестов (`setSystemGestureExclusionRects`).

### Футпринт на маленьком экране

- **Мобильные пресеты вида** (на ПК механизм пресетов уже есть):
  - «Телефон: Bid×Ask» — шрифт цифр не мельче 9–10 точек;
  - «Телефон: дельта» — одно число в ячейке и заливка;
  - «Телефон: профиль бара» — без чисел, строки и POC/VA, как в DeepCharts.
- **Режим ячейки выбирается по ширине колонки.** При отдалении Bid×Ask сам переходит в одно число, потом в одну заливку, потом в свечу. Это продолжение автогруппировки уровней, которая уже есть на ПК.
- **Атлас глифов** (`fontdue`) растрируется в физических пикселях. При плотности 2.6–3.75 нужно проверить его размер, чтобы крупные шрифты не вытесняли друг друга.

## 5. Индикаторы: что и когда

Все индикаторы считает тот же движок и рисует тот же код графика. Работа по каждому сводится к трём вещам: управление пальцем, страница настроек на маленьком экране и читаемость.

| Этап | Что | Замечание |
|---|---|---|
| MVP | **Футпринт целиком:** все режимы чисел (Bid×Ask, дельта, объём, объём+дельта), заливки и гистограммы, нормировка, профиль бара с POC и VA, рамки максимумов, диагональные дисбалансы, их стеки и зоны до возврата цены, незавершённые аукционы, таблица статистики | основа |
| MVP | Бары по времени (5 с – сутки), по числу сделок, объёму, обороту; любые из 11 потоков 6 бирж, сводная цена | как на ПК |
| MVP | **Volume Profile** по видимой области и по сессиям, VAH/VAL/POC, непротестированные POC | твой уровень входа |
| MVP | **VWAP** день/неделя/месяц/якорь ±σ | |
| MVP | **CVD** (перп и спот, по биржам) с **ΔOI** | OI опрашивается раз в 5 с по REST — копейки трафика |
| MVP | **Big Trades**, **ликвидации** и каскады | |
| Этап 3 | **Уровни поглощения** (ленточная половина effort), строки «Расхождение», «Лямбда», «Давление», «Напряжённость» | твоё подтверждение на уровне |
| Этап 3 | **Скорость ленты** («Темп»), **дельта-профиль** | |
| Этап 5 | **Стакан на графике**, **долив в профиле бара**, книжная половина effort («Защита», «Снято лимиток») | нужны сокеты стакана — §6 |
| Этап 5 | Вкладки «Стакан» и «Тепловая карта» | |
| Этап 6 | GEX по опционам Deribit | тяжёлая докачка ленты опционов |

## 6. Данные, сеть и батарея

Объёмы по замерам из README ПК-версии:

- **Сделки** всех 10 потоков — около 5 КБ/с, то есть около 18 МБ в час.
- **Стакан** четырёх перпов — 43 КБ/с, около 155 МБ в час.
- **Дневной архив** одной биржи — около 165 МБ за пропущенный день.
- **Сутки сделок** — около 8 млн, это 120–180 МБ памяти. У S25 Ultra 12 ГБ, так что двое суток помещаются, но Android выгружает из памяти в первую очередь крупные фоновые процессы.

Мобильный профиль по умолчанию (всё меняется в настройках):

| Настройка | ПК | Телефон | Почему |
|---|---|---|---|
| Сделки в памяти (`footprint_days`) | 2 | 1 (с начала текущей сессии) | память и время пересборки |
| Минутные свечи (`candle_days`) | 30 | 30 | 19 МБ на все потоки — дёшево, нужны для контекста |
| Дневные архивы | всегда | только по Wi-Fi | 165 МБ за день |
| REST-докачка дыр | всегда | всегда | небольшие объёмы |
| Сокеты стакана | по необходимости + запись | только пока открыт стакан, тепловая карта или стакан на графике; по мобильной сети — с подтверждением | 155 МБ в час |
| Запись стакана (`record_book`) | да | нет | ≈ 590 МБ в сутки |
| Хранить на диске (`keep_days`) | 30 | 7 | память телефона |
| `live_fps` | 20 | 15 | батарея |

- **Смена сети** (Wi-Fi ↔ LTE). Сокеты рвутся, и `conn.rs` их уже переподключает, но только по тайм-ауту тишины. Kotlin-слой следит за `ConnectivityManager` и сразу передаёт в Rust: «сеть сменилась» (переподключить всё без ожидания) и «сеть безлимитная или нет» (разрешение для архивов).
- **Часы.** `ClockSync` уже учитывает расхождение часов устройства со временем бирж и скачки системного времени, в том числе после сна. Это прямо нужно телефону.
- **Перенос с ПК:**
  - историю можно скопировать по USB с ПК в `Android/data/<пакет>/files/data/ticks/` — формат тот же;
  - `settings.json` с ПК импортируется через выбор файла. Формат тот же, лишнее отсечёт `normalize`, раскладка доков ПК игнорируется.

## 7. Жизненный цикл Android

- **Движок — один на процесс.** Android пересоздаёт Activity, и `android_main` может вызываться повторно. Поэтому `Engine` живёт в статическом синглтоне, а экран к нему подключается и отключается. Поворот экрана Activity не пересоздаёт (`configChanges` в манифесте), egui получает просто новый размер.
- **Пауза.** При уходе с экрана система забирает поверхность для рисования. GPU-ресурсы пересоздаются при возврате, сцены собираются из серий заново (это дёшево). Запись сбрасывается на диск при уходе в фон: дальше процесс могут убить без предупреждения. На ПК для этого закрывают окно через WM_CLOSE, а не убивают процесс.
- **Работа в фоне** — настройка с двумя режимами:
  - **«Пауза».** Через N минут в фоне сокеты закрываются. При возврате дыры докачиваются по REST — это уже работает для Binance, OKX, Bitget, Coinbase и Deribit. Bybit до ночного архива идёт свечами, как на ПК после перезапуска.
  - **«Запись и оповещения».** Foreground-служба с постоянным уведомлением «OrderFlow: запись идёт». Сокеты, движок, запись и поток оповещений работают, график не рисуется.
    - Тип службы — `specialUse`: `dataSync` в Android 15+ ограничен 6 часами в сутки. Для APK не из Google Play `specialUse` проблем не создаёт.
    - Samsung усыпляет фоновые приложения. Нужно один раз выставить «Батарея → Без ограничений» — инструкция в README и подсказка в приложении.
- **Оповещения.** `alerts.rs` уже работает в своём потоке, 4 раза в секунду, без интерфейса. На телефоне карточка в углу окна заменяется системным уведомлением со звуком и вибрацией. Сработают уровень цены, крупная сделка, ликвидация и начало каскада. Звук — системный канал уведомлений, свой проигрыватель (`sound.rs`) не нужен.
- **`onTrimMemory`** освобождает буферы сцен и кэши индикаторов, сами серии остаются.

## 8. Сборка и выпуск

- **Инструменты:**
  - Rust 1.98.1, как в ПК-версии, плюс цель `aarch64-linux-android`;
  - Android NDK r27 (LTS), `cargo-ndk`, JDK 17, Gradle;
  - `minSdk` 30, `targetSdk` 35;
  - только `arm64-v8a`, для эмулятора можно добавить `x86_64`.
- **C-зависимости.** `zstd-sys` собирается компилятором NDK. OpenSSL уходит вместе с `native-tls` (§3.3).
- **CI** (GitHub Actions этого репозитория):
  - на каждый пуш: `fmt`, `clippy -D warnings`, тесты `of-mobile` на хосте, сборка `.so` через `cargo ndk` и `assembleDebug`;
  - на метку `v*`: подписанный release-APK во вкладке Releases. Ключ подписи хранится в секретах репозитория.

  Ноутбук для сборки не нужен (на нём первая сборка ПК-версии идёт 15 минут): APK скачивается на телефон из Releases и ставится.
- **Отладка.** `cargo ndk -t arm64-v8a -o android/app/src/main/jniLibs build --release`, затем `./gradlew installDebug`. Журнал смотреть через `adb logcat` (крейт `android_logger`) или в файле `logs/ofmobile.log` в папке приложения, как на ПК.
- **Обслуживание.** Отдельный `MAINTENANCE.md` по образцу ПК-версии: как обновить `rev` ПК-кода, как выпустить APK, что делать, если биржа поменяла API. Исправление в ядре ПК-версии попадает на телефон сдвигом `rev`.

## 10. Риски

| Риск | Чем грозит | Что делаю |
|---|---|---|
| eframe на Android: ошибки при паузе и возврате, клавиатура, отступы | падения, неудобный ввод | этап 0 проверяет именно это. Запасной путь — своя связка `egui-winit` + `egui-wgpu` без eframe (несколько сотен строк, полный контроль). Числа — своей клавиатурой |
| Нагрев и батарея | троттлинг, разряд за час-два | рисование только по событию, `live_fps` 15, стакан только по запросу. На этапе 2 замер расхода за час с живым футпринтом |
| Samsung убивает фоновый процесс | дыры в записи, не приходят оповещения | foreground-служба и «Без ограничений». Дыры закрывает REST — это уже работает |
| Мобильный трафик | лишние гигабайты | профиль §6, архивы и стакан по Wi-Fi |
| Цифры в ячейках мелкие на 6.9″ | футпринт не читается | мобильные пресеты, выбор режима по ширине, проверка на устройстве |
| Код ПК и телефона расходится | двойная работа | общий `of-ui`, `rev`, CI обеих версий |
| Конфликт с системным жестом «назад» | закрывается приложение | перехват в Kotlin, исключение краёв графика |
